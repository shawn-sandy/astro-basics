## Common Error Messages

### "Database not configured"

This error appears when the system can't find valid Supabase credentials.

**Symptoms:**
- `getDatabase()` throws "No database configured. Set SUPABASE_URL, SUPABASE_ANON_KEY and SUPABASE_SERVICE_ROLE_KEY in your environment variables."
- API endpoints return 503 Service Unavailable errors
- Dashboard shows "Database service unavailable"
- `npm run db:status` shows `Selected Provider: none`

<Tabs>
  <TabItem label="Quick Fix">
    <Steps>
      1. Check what's missing:
         ```bash
         npm run db:status
         ```

      2. Run the setup wizard:
         ```bash
         npm run db:wizard
         ```

      3. Follow the interactive prompts to enter your Supabase project URL, anon key, and service role key
    </Steps>
  </TabItem>
  <TabItem label="Manual Fix">
    <Steps>
      1. Check your `.env` file has the required variables:
         ```bash
         grep SUPABASE .env
         ```

      2. Add missing credentials to `.env` (unreplaced `YOUR_...` placeholders count as not set):
         ```env
         SUPABASE_URL=https://your-project.supabase.co
         SUPABASE_ANON_KEY=eyJ...
         SUPABASE_SERVICE_ROLE_KEY=eyJ...
         ```

      3. Verify file exists and has content:
         ```bash
         ls -la .env
         wc -l .env  # Should show more than just comments
         ```
    </Steps>
  </TabItem>
</Tabs>

### "Connection failed" During Operations

Database operations timeout or fail to connect to the server.

**Symptoms:**
- Database operations timeout
- "Failed to connect" errors in logs
- API endpoints return 500 Internal Server errors

<Aside type="tip" title="Debug Network Issues">
Test connectivity outside the application to isolate network vs. configuration issues.
</Aside>

<Tabs>
  <TabItem label="Network Diagnosis">
    <Steps>
      1. Check the Supabase configuration:
         ```bash
         npm run db:manage -- test --verbose
         ```

      2. Check network connectivity:
         ```bash
         curl -I https://your-project.supabase.co
         ```

      3. Test from different network if possible
    </Steps>
  </TabItem>
  <TabItem label="Credential Issues">
    <Steps>
      1. Verify your Supabase project is active
         - Visit: https://supabase.com/dashboard/projects
         - Check project status and billing

      2. Test with fresh credentials
    </Steps>
  </TabItem>
  <TabItem label="Server Issues">
    - Check the Supabase status page for outages
    - Verify database instance is running
    - Check for scheduled maintenance windows
    - Verify database instance performance tier
  </TabItem>
</Tabs>

### "Schema validation failed"

Operations succeed but data doesn't match expectations.

**Symptoms:**
- Missing tables or columns
- Type conversion errors

<Tabs>
  <TabItem label="Quick Schema Check">
    ```bash
    npm run db:schema
    # Checks the Supabase configuration and lists the expected tables
    ```
  </TabItem>
  <TabItem label="Migration Fix">
    <Steps>
      1. **Apply the SQL migrations** in `scripts/migrations/`:
         ```bash
         psql "$DATABASE_URL" -f scripts/migrations/001_core_schema.sql
         ```
         Or paste the SQL into the Supabase SQL editor. See `scripts/migrations/README.md` for the order.

      2. **Manual Schema Verification**:
         ```bash
         # List tables in current database
         npm run db:manage tables

         # Compare with expected schema in docs
         ```
    </Steps>
  </TabItem>
</Tabs>

## Supabase Issues

<CardGrid>
  <Card title="Invalid API Key" icon="key">
    **Problem**: Using wrong key type for operations
    
    **Fix**:
    ```env
    # ❌ Don't use anon key for server operations
    SUPABASE_ANON_KEY=eyJ...
    
    # ✅ Use service role for server operations
    SUPABASE_SERVICE_ROLE_KEY=eyJ...
    ```
  </Card>
  <Card title="RLS Policy Violation" icon="shield">
    **Problem**: Row Level Security blocks operations
    
    **Fix**:
    - Check RLS policies in Supabase Dashboard
    - Ensure service role can access required tables
    - Review policy conditions for your use case
  </Card>
  <Card title="Project Paused" icon="pause">
    **Problem**: Free tier project paused due to inactivity
    
    **Fix**:
    - Visit Supabase Dashboard
    - Unpause project in Settings
    - Consider upgrading plan if needed frequently
  </Card>
</CardGrid>

## Development Environment Issues

### Module Import Errors

**Symptoms:**
- Import errors for database modules
- TypeScript compilation fails
- "Cannot find module" errors

**Solutions:**

<Tabs>
  <TabItem label="Node Modules Reset">
    <Steps>
      1. Clear Node modules and package lock:
         ```bash
         rm -rf node_modules package-lock.json
         ```

      2. Reinstall dependencies:
         ```bash
         npm install
         ```

      3. Check TypeScript configuration:
         ```bash
         npm run type-check
         ```
    </Steps>
  </TabItem>
  <TabItem label="Cache Issues">
    <Steps>
      1. Clear npm cache:
         ```bash
         npm cache clean --force
         ```

      2. Clear TypeScript cache:
         ```bash
         npx tsc --build --clean
         ```

      3. Restart development server:
         ```bash
         npm run start
         ```
    </Steps>
  </TabItem>
</Tabs>

### Hot Reload Not Working

Database configuration changes don't take effect without server restart.

**Expected Behavior**: Environment values are read once and cached, so changes to `.env` need a dev server restart.

**Troubleshooting Steps:**

<Steps>
1. **Check the Configuration** in `.env`:
   ```bash
   # Reads .env directly, so it shows changes immediately
   npm run db:status
   ```

2. **Test API Endpoint** against the running server:
   ```bash
   curl http://localhost:4321/api/supabase-test
   # Response shows whether the running server can query Supabase
   ```

3. **Force Restart** if needed:
   ```bash
   # Kill existing processes
   pkill -f "npm run"
   
   # Start fresh
   npm run start
   ```
</Steps>

### Production vs Development Behavior

**Symptoms:**
- Works locally but fails in production

<Tabs>
  <TabItem label="Environment Variables">
    <Steps>
      1. **Check Production Environment Variables**:
         - Verify `SUPABASE_URL`, `SUPABASE_ANON_KEY`, and `SUPABASE_SERVICE_ROLE_KEY` are present
         - Use same credential format as local

      2. **Validate Network Access**:
         - Test database connectivity from production environment
         - Check firewall rules and security groups
    </Steps>
  </TabItem>
  <TabItem label="Configuration Debugging">
    <Steps>
      1. **Compare Environment Files**:
         ```bash
         # Local
         grep SUPABASE .env | sort
         
         # Production (if accessible)
         env | grep SUPABASE | sort
         ```

      2. **Test Production Database Access**:
         ```bash
         # From production environment
         npm run db:manage test
         npm run db:manage health
         ```
    </Steps>
  </TabItem>
</Tabs>

## API Endpoint Issues

### Silent API Failures

**Symptoms:**
- No errors but operations don't work
- Empty results from database queries
- API returns success but no data changes

<Steps>
1. **Test a Database Query** through the running server:
   ```bash
   curl http://localhost:4321/api/supabase-test
   ```

2. **Check API Logs** in development:
   ```bash
   npm run dev
   # Look for console errors in terminal
   ```

3. **Verify Database Tables**:
   ```bash
   npm run db:manage tables
   ```

4. **Check Permissions**:
   - Review RLS policies in dashboard
   - Verify service role permissions
</Steps>

## File System Issues

### Permission Denied Errors

**Symptoms:**
- Cannot read or write `.env` files
- Script execution fails with permission errors

<Steps>
1. **Fix File Permissions**:
   ```bash
   chmod 644 .env
   chmod +x scripts/*.js
   ```

2. **Check Directory Permissions**:
   ```bash
   ls -la .
   # Verify you can read/write in current directory
   ```

3. **Fix Ownership Issues** (if needed):
   ```bash
   # Only if files are owned by different user
   sudo chown $USER:$USER .env
   ```
</Steps>

### Git Conflicts with Backup Files

**Problem**: Git wants to commit `.env.backup` files, causing merge conflicts.

<Steps>
1. **Ensure Backup Files are Ignored**:
   ```bash
   echo ".env.backup*" >> .gitignore
   echo ".env.*.backup" >> .gitignore
   ```

2. **Remove from Git** if already tracked:
   ```bash
   git rm --cached .env.backup
   git rm --cached .env.*.backup
   ```

3. **Clean Up Repository**:
   ```bash
   git add .gitignore
   git commit -m "Add .env backup files to .gitignore"
   ```
</Steps>

## Advanced Debugging

### Enable Debug Mode

For detailed troubleshooting information, add `--verbose` (after `--` so npm passes it to the script):

```bash
# Get detailed output for all operations
npm run db:manage -- status --verbose
npm run db:manage -- health --verbose
```

### Manual Database Testing

Test the Supabase connection directly outside the abstraction layer:

```bash
node --env-file=.env --input-type=module -e "
import { createClient } from '@supabase/supabase-js';
const client = createClient(
  process.env.SUPABASE_URL,
  process.env.SUPABASE_SERVICE_ROLE_KEY
);
const { data, error } = await client
  .from('messages')
  .select('count');
console.log('Result:', data, 'Error:', error);
"
```

### Environment Variable Debugging

Check for hidden characters or configuration issues:

```bash
# Check all database-related environment variables
env | grep SUPABASE | sort

# Check for invisible characters or extra spaces
od -c .env | grep SUPABASE

# Check what the database scripts read from .env
npm run db:status
```

## Recovery Procedures

### Complete System Reset

If all else fails, reset the entire database configuration:

<Steps>
1. **Backup Current State**:
   ```bash
   cp .env .env.emergency-backup
   ```

2. **Run Fresh Setup**:
   ```bash
   npm run db:wizard
   # Follow prompts to reconfigure from scratch
   ```

3. **Test New Configuration**:
   ```bash
   npm run db:status
   npm run db:manage test
   ```

4. **Restore if Needed**:
   ```bash
   # If new setup doesn't work
   cp .env.emergency-backup .env
   ```
</Steps>

When reporting issues or asking for help, collect this information:

```bash
# Create comprehensive diagnostic report
{

```

## Prevention Best Practices

### Regular Health Checks

Add these to your development routine:

```bash
# Weekly health check
npm run db:status
npm run db:manage health

# Before major changes
npm run db:schema
```

### Safe Development Workflow

<Steps>
1. **Keep Emergency Backup** before experiments:
   ```bash
   # Maintain a known-good configuration
   cp .env .env.known-good
   ```

2. **Validate Configuration** after changes:
   ```bash
   npm run db:schema
   npm run db:manage test
   ```
</Steps>

### Version Control Safety

```bash
# Always check before committing
git status | grep -E "(\.env|backup)" && echo "⚠️  Check .env files"

# Verify .gitignore is protecting secrets
git ls-files | grep -E "\.env" && echo "⚠️  .env files in git!"
```
