# Installation Guide

This guide covers different ways to install and set up astro-basics depending on your use case.

## System Requirements

- **Node.js**: Version 18 or higher
- **npm**: Version 8 or higher (or yarn/pnpm equivalent)
- **Git**: For cloning the repository

## Installation Options

### Full Project Setup

For complete project with all features, examples, and development tools:

```bash
# Clone the repository
git clone https://github.com/shawn-sandy/astro-basics.git

# Navigate to project directory
cd astro-basics

# Install dependencies (takes ~4 minutes)
npm install

# Set up environment
cp .env.example .env

# Install pre-commit hooks
npm run prepare

# Install Playwright browsers (for E2E tests)
npx playwright install
```

### Component Library Only

To use astro-basics components in an existing Astro project:

```bash
npm install astro-basics-website
```

## Post-Installation Setup

### 1. Environment Configuration

Edit your `.env` file with the required keys:

```env
# Authentication (Required)
PUBLIC_CLERK_PUBLISHABLE_KEY=pk_test_your_key_here
CLERK_SECRET_KEY=sk_test_your_key_here

# Site URL
SITE_URL=http://localhost:4321

# Database (Optional)
SUPABASE_URL=https://your-project.supabase.co
SUPABASE_ANON_KEY=eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...
```

:::note[Where to find these credentials?]
Need help locating your API keys?

- **Clerk keys**: [Clerk Dashboard](https://dashboard.clerk.com) → API Keys
- **Supabase keys**: [Supabase Dashboard](https://supabase.com/dashboard) → Settings → API
- **Detailed instructions**: See the [Complete Setup Guide](/guide/getting-started/setup/#2-get-credentials) for step-by-step instructions with screenshots.
:::

### 2. Database Setup (Optional)

:::tip[Configure Roles Before Database Setup]
If you plan to customize user roles, **configure them before running database migrations**. Role configuration generates database migrations that define your role schema. See [Section 3: Role Configuration](#3-role-configuration-optional) below for details, or skip to use the default 3-tier system (member, admin, super_admin).
:::

The project uses **Supabase** (PostgreSQL) as its database.

#### Interactive Setup (Recommended)

```bash
# Use the database wizard for guided setup
npm run db:wizard
```

The wizard prompts for your Supabase project URL, anon key, and service role key (required for database queries), then tests the connection.

#### Manual Setup

```bash
# Check database status and configuration
npm run db:status

# Verify connection
npm run db:manage test

# Apply migrations (SQL files in scripts/migrations/).
# Export your Supabase PostgreSQL connection string first (Project Settings → Database);
# it is not the API URL that SUPABASE_URL holds.
export DATABASE_URL="postgresql://postgres:[password]@[project-ref].supabase.co:5432/postgres"
psql "$DATABASE_URL" -v ON_ERROR_STOP=1 -f scripts/migrations/001_core_schema.sql
psql "$DATABASE_URL" -v ON_ERROR_STOP=1 -f scripts/migrations/002_security_policies.sql
psql "$DATABASE_URL" -v ON_ERROR_STOP=1 -f scripts/migrations/006_messages.sql
```

You can also paste migration files into the Supabase SQL editor.

See the [Complete Setup Guide](/guide/getting-started/setup/) and [Environment Configuration](/guide/environment-configuration/) for detailed configuration.

### 3. Role Configuration (Optional)

The project includes a **configurable role system** for managing user permissions and access control.

#### Default Roles

By default, astro-basics comes with a 3-tier role system:

- **member** (Level 1) - Default role for new users
- **admin** (Level 2) - Administrative access
- **super_admin** (Level 3) - Full system control

These roles are ready to use without any configuration.

#### Customizing Roles

If you need custom roles for your application (e.g., author, moderator, editor):

**1. Edit the configuration file:**

```bash
vim config/roles.config.ts
```

**2. Add or modify roles:**

```typescript
export const roleConfig: RoleConfig = {
  roles: [
    { name: 'member', level: 1, label: 'Member' },
    { name: 'author', level: 2, label: 'Author' }, // Custom
    { name: 'moderator', level: 3, label: 'Moderator' }, // Custom
    { name: 'admin', level: 4, label: 'Admin' },
    { name: 'super_admin', level: 5, label: 'Super Admin' },
  ],
  coreRoles: ['member', 'admin', 'super_admin'],
}
```

**3. Generate types and migrations:**

```bash
# Generate TypeScript types and database migrations
npm run setup:roles

# Apply the migration
psql "$DATABASE_URL" -v ON_ERROR_STOP=1 -f scripts/migrations/XXX_user_roles.sql
```

**4. Commit your changes:**

```bash
git add config/ src/types/ scripts/migrations/
git commit -m "Configure custom roles"
```

See the [Complete Setup Guide - Role Configuration](/guide/getting-started/setup/#step-4-role-configuration) and [Configurable Roles Guide](/guide/configurable-roles/) for detailed instructions and templates.

### 4. Verify Installation

Start the development server:

```bash
npm run start
```

Visit `http://localhost:4321` to see your site running.

## Troubleshooting

### Common Issues

**1. Installation takes too long**

- Expected: npm install takes ~4 minutes
- Warnings during installation are normal

**2. Authentication errors**

- Ensure `PUBLIC_CLERK_PUBLISHABLE_KEY` and `CLERK_SECRET_KEY` are set
- Use dummy keys for build-only testing

**3. E2E tests failing**

- Run `npx playwright install` to install browsers
- Ensure dev server is running on port 4321

**4. Build warnings**

- getStaticPaths warnings in dynamic pages are expected
- These don't affect functionality
