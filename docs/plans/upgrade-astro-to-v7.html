Context

astro-basics currently runs on astro ^6.0.0 with SSR (output: 'server') and a full adapter stack — @astrojs/netlify, @astrojs/node, @astrojs/vercel — selected at deploy time by the ASTRO_ADAPTER env var, plus integrations @astrojs/react, @astrojs/mdx, @astrojs/sitemap, @astrojs/rss, and @astrojs/starlight. The official v6→v7 upgrade guide lists eight breaking changes, but a scan of this codebase shows only two actually apply: the new default Rust compiler (stricter HTML — unclosed non-void tags now error, and invalid markup is no longer auto-corrected) which recompiles all ~69 .astro files (35 components, 4 layouts, 30 pages), and the compressHTML default flipping from true to 'jsx', which strips inter-element whitespace and can silently drop spaces between inline elements.

The other six guide items are confirmed absent: no src/fetch.ts, no getContainerRenderer() usage, no astro:transitions internals, no @astrojs/db, no experimental config block, and no wired remark/rehype plugins (so the Sätteri markdown-processor default is a no-op here). The remaining work is the routine but mandatory part of any major bump: moving astro and every @astrojs/* package to v7-compatible versions in lockstep, reconciling third-party Astro integrations (Clerk, astro-embed, Spotlight) that @astrojs/upgrade does not touch, and absorbing the Vite 8 dependency bump that ships with v7. Node is already well ahead of any requirement (v26 local, engines: ">=22.12.0").
